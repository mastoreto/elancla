# Plan — Fase 0.6: archivos y multimedia

## Contexto

0.2–0.5 dejaron la API (Hono en el CRM), RBAC con `PERMISSIONS` y `writeAudit` en la misma
transacción. La 0.6 (D-06, ESRE 2.2) agrega subir y servir archivos: imágenes públicas con variantes
y documentos privados con URL firmada de vida corta. No hay todavía módulos dueños (blog, órdenes de
compra): la 0.6 entrega el mecanismo y cada módulo futuro lo engancha.

Siguiendo "Docker primero": todo se construye y valida contra **MinIO en `docker-compose`**. Los
buckets B2, la key por bucket, `media.<dominio>` en Cloudflare, CORS de B2 y el cron de Vercel en
producción quedan como checklist para 0.8 (se documentan acá, no se aprovisionan).

**Ejecución: la implementación se hace con Sonnet 5.5** (`claude-sonnet-5-5`), siguiendo este plan
al pie de la letra. Después Opus revisa el diff, corre los tests, prueba en el navegador (Docker
local) y **cierra con PR a `develop` con tests en verde**, sin `Co-Authored-By`.
**Rama:** `feat/storage` desde `develop` actualizado. Un commit por paso de la sección "Orden".

## Decisiones (defaults, ajustables)

| Tema | Decisión |
|---|---|
| Adaptador | **Uno solo**, S3-compatible, sobre `aws4fetch` (≈3 KB, `fetch` + SigV4; corre en Node/Vercel y en Bun). Ni `@aws-sdk/*` (peso) ni `Bun.S3Client` (en producción la API corre en Node dentro de Next). MinIO lo cubre en dev y tests. |
| Puerto | `FileStorage` **por bucket** (sin parámetro de bucket): `presignUpload`, `presignDownload`, `head`, `get`, `put`, `delete`. `get`/`put` se suman a los 4 de la fase porque `finalize` lee el original y sube variantes. Dos instancias: `getStorage("private")`, `getStorage("public")`, cada una con su propia key (B2 restringe una key a un bucket). |
| Cuarentena | **Toda subida va al bucket privado** (`<organizationId>/<fileId>`). Nada sin verificar llega nunca a `media.<dominio>` (un PUT directo al público serviría HTML/SVG arbitrario desde nuestro dominio antes de `finalize`). Para imágenes públicas, `finalize` genera las variantes en el bucket público y el original queda privado (permite regenerar y no publica EXIF). |
| Propósito | `MEDIA_PURPOSES` en `contracts` decide todo: bucket de las variantes, tipos permitidos, tamaño máximo y permisos. Arranca con dos: `contentImage` (público; JPEG/PNG/WebP/AVIF; 15 MB; sube con `content:create`) y `voucherDocument` (privado; PDF/JPEG/PNG/WebP; 20 MB; sube con `vouchers:create`, descarga con `vouchers:view`). Cada módulo futuro agrega el suyo (p. ej. acta en Word, D-54). |
| Permiso | **Sin recurso `media` nuevo** (desvío de la fase, que pedía `media:*` + permiso del dueño): sería una segunda llave para la misma puerta. Manda el permiso del propósito. Alcance en descarga: `all` ve todo; `own` y `ministry` solo lo que subió el usuario (`ponytail:` hasta que 2.3 enlace archivos a su orden de compra y aplique la policy del dueño). |
| Modelo | `MediaFile` → `media_files`, **no `File`**: el tipo que genera Prisma taparía el `File` global (DOM/Node) que usa el código de subida. El bucket no se guarda: se deriva del propósito. |
| Tamaño y tipo | El PUT prefirmado firma `content-type` y `content-length` (el storage rechaza otro tipo o tamaño si lo soporta). La barrera real es `finalize`: `head` (tamaño = declarado ≤ máximo) → `get` → magic bytes → SHA-256. Si falla: borra objeto y fila, audita `media.rejected`, responde 422. |
| Magic bytes | Función propia `detectContentType(bytes)` con tabla de firmas solo de la allowlist (JPEG, PNG, WebP, AVIF, PDF). Sin dependencia (`file-type` es mucho para 5 firmas). |
| Variantes | `sharp` (dep. directa y fija de `apps/api`; hoy no está instalado). Anchos `480, 960, 1600`, sin agrandar (si el original es más chico, una sola variante a su ancho). `webp` + `avif` (`effort: 4`). Metadatos fuera (default de sharp: sin EXIF/GPS). `limitInputPixels: 40_000_000` contra bombas de descompresión. Síncrono dentro de `finalize`: no hay cola (`ponytail:` cola cuando una subida tarde más que el timeout de la función). |
| Claves públicas | `<organizationId>/<fileId>/<width>.<format>`. El `fileId` (UUIDv7) nunca se reutiliza y el contenido nunca cambia, así que cumple lo de D-06 ("nombre con hash") para caché inmutable sin calcular un hash en la clave. |
| Descarga | `GET /media/:id/download` → `{ url, expiresAt }` (JSON, no 302: el cliente tipado lo maneja simple). URL de **60 s** con `response-content-disposition=attachment`. Auditoría **estricta**: si `writeAudit` falla, no se emite URL. `Cache-Control: no-store`. |
| Limpieza | Pendientes con más de **1 h** se borran (objeto + fila, auditado con actor `{ id: null, label: "cron" }`). Vercel Hobby solo permite cron diario: corre una vez por día. Endpoint `GET /internal/media/purge` con `Authorization: Bearer CRON_SECRET` (comparación en tiempo constante) + script `media:purge` para correrlo a mano. |
| Env | Esquema **propio y perezoso** en `core/storage` (`getStorageEnv()`), no en `getApiEnv`: el CLI `invite` y el resto de la API no necesitan credenciales de S3. |
| UI CRM | Mínima para validar en navegador: `lib/media/uploadMedia` + `ContentImageDropzone` sube de verdad y muestra la vista previa. Los formularios siguen sin guardar (eso es 1.4/2.3); los archivos `ready` sin dueño quedan (`ponytail:` se limpian cuando existan dueños). |

## Cambios de BD (`packages/db`)

- Enums `MediaPurpose { contentImage, voucherDocument }`, `MediaFileStatus { pending, ready }`.
- `MediaFile` → `media_files`: `id` (UUIDv7), `organizationId` (FK, `onDelete: Restrict`),
  `purpose`, `status @default(pending)`, `key String @unique`, `contentType`, `size Int` (declarado;
  en `ready` es el real), `checksum String?` (SHA-256 hex), `originalName String` (saneado, ≤ 200),
  `variants Json?` (`[{ width, height, format, key, size }]`), `uploadedById uuid?` (FK `User`,
  `onDelete: SetNull`), `createdAt`, `finalizedAt DateTime?`.
- Índice `(organizationId, status, createdAt)` (lo usa la purga).
- Migración `…_media_files`: tablas/enums y termina con `SELECT public.app_secure_tables()` (tabla
  común: recibe la policy genérica, no la de solo-inserción).
- `TENANT_MODELS` (`apps/api/src/core/tenancy/tenantModels/tenantModels.ts`): agregar `MediaFile`.

## Contratos (`packages/contracts/src/media/`)

- `MEDIA_PURPOSES` (`as const`, estilo `PERMISSION_CATALOG`): por propósito `visibility`
  (`public | private`), `contentTypes`, `maxBytes`, `uploadPermission`, `downloadPermission?`
  (solo privados). Referencia permisos vía `PERMISSIONS`, nunca strings.
- `createUploadBody` (`strictObject`: `purpose`, `contentType`, `size`, `fileName`; valida
  `contentType ∈ purpose.contentTypes` y `size ≤ maxBytes` con `superRefine`),
  `uploadTicketDto` (`id`, `uploadUrl`, `headers` a reenviar, `expiresAt`), `mediaFileDto` (`id`,
  `purpose`, `status`, `contentType`, `size`, `originalName`, `variants: { width, format, url }[]`,
  `createdAt`), `downloadLinkDto` (`url`, `expiresAt`).
- `AUDIT_ACTIONS.media`: `uploadRequested`, `finalized`, `rejected`, `downloadIssued`, `purged`
  (`media.upload.requested`, …).

## API (`apps/api`)

**`src/core/storage/`** (cada unidad en su carpeta con barrel):
- `types/`: `FileStorage`, `StoredObject { size, contentType }`, opciones de presign.
- `createS3Storage/`: adaptador sobre `AwsClient` de `aws4fetch` (`signQuery: true` para presign,
  path-style). `head` devuelve `null` en 404. `presignUpload({ key, contentType, size, expiresIn })`
  firma `content-type` y `content-length`. `presignDownload({ key, expiresIn, fileName })`.
- `getStorageEnv/`: `S3_ENDPOINT`, `S3_PRESIGN_ENDPOINT` (opcional, default `S3_ENDPOINT`; el host
  que ve el navegador), `S3_REGION` (default `us-east-1`), `S3_PRIVATE_BUCKET`,
  `S3_PRIVATE_KEY_ID`, `S3_PRIVATE_SECRET`, `S3_PUBLIC_BUCKET`, `S3_PUBLIC_KEY_ID`,
  `S3_PUBLIC_SECRET`, `MEDIA_PUBLIC_BASE_URL`, `CRON_SECRET` (≥ 32).
- `getStorage/`: `getStorage(visibility)` memoizado.
- `fileStorage.contract.ts` (suite de contrato exportada como función que recibe una
  `FileStorage`) + `createS3Storage.test.ts` que la corre contra MinIO.

**`src/core/audit/auditSource`**: agregar `auditSourceForSystem(organizationId, label)`
(generaliza `auditSourceForCli`; `cli` pasa a usarla).

**Módulo `modules/media/`** (`data/ domain/ mappers/ useCases/ media.routes.ts`, barrel):
- `domain/detectContentType/`, `domain/sanitizeFileName/`, `domain/mediaKey/` (claves original y
  variantes), `domain/canDownload/` (propósito + alcance + `uploadedById`).
- `lib/renderVariants/`: `sharp` → `{ width, height, format, body }[]`.
- `useCases/requestUpload`: valida propósito y permiso (`requirePermission` dinámico por propósito:
  `ForbiddenError` si `scopeOf(access, purpose.uploadPermission) === null`), crea fila `pending` +
  audita en tx, presign 5 min **después** del commit.
- `useCases/finalizeUpload`: solo el que subió (si no, 404); `status !== pending` ⇒ 409. Fuera de
  tx: `head`, `get`, `detectContentType`, hash, variantes (`put` al público). Después, en tx:
  `ready` + `checksum` + `variants` + `finalizedAt` + audita `media.finalized`. Si la verificación
  falla: `delete` del objeto, en tx borra la fila + audita `media.rejected` (motivo en `metadata`),
  422. Si falla la tx tras subir variantes: borrar variantes (best-effort) y relanzar.
- `useCases/issueDownload`: 404 si no existe en la organización, 409 si es público o `pending`,
  `ForbiddenError` si `!canDownload`; `writeAudit(db, …, media.downloadIssued)` y recién después
  firma 60 s.
- `useCases/purgeStaleUploads(now)`: recorre todas las organizaciones (cliente `db` sin scope a
  propósito, documentado), por fila: `delete` del objeto y, en tx, borra fila + audita
  `media.purged` con `auditSourceForSystem(orgId, "cron")`. Devuelve la cantidad.
- Rutas: `POST /media/uploads` (201), `POST /media/uploads/{id}/finalize` (200),
  `GET /media/{id}/download` (200) con `requireSession` (el permiso se resuelve por propósito dentro
  del use case; declarar el acceso con `declareAccess` para que la matriz lo vea).
  `GET /internal/media/purge` en `modules/media/internal.routes.ts` con guard `requireCronSecret`
  (401 sin bearer válido). Registrar en `app.ts`.
- `scripts/purgeMedia/purgeMedia.ts` + script `media:purge` en `package.json`.
- `package.json`: `aws4fetch` y `sharp` con versión fija.

## Tests obligatorios (bun test, Postgres + MinIO reales)

- **Contrato del puerto** (contra MinIO): presign PUT → `head` → `get` → presign GET descargable →
  `delete` → `head` null; `put`/`get` ida y vuelta; PUT con otro `content-type` es rechazado.
- **Extensión falsa** → rechazada en `finalize`: PDF declarado `image/png`, HTML subido como
  `image/jpeg` ⇒ 422, objeto y fila borrados, fila `media.rejected` en auditoría.
- Tamaño real ≠ declarado ⇒ 422. Doble `finalize` ⇒ 409. `finalize` de otro usuario ⇒ 404.
- Imagen válida: variantes en el bucket público, ningún ancho mayor al original, sin EXIF
  (`sharp(variant).metadata().exif === undefined` partiendo de un JPEG con EXIF GPS).
- **Descarga privada**: sin permiso ⇒ 403 y ninguna fila `media.downloadIssued` (sí
  `permission.denied`); con permiso ⇒ URL descargable, fila auditada con actor/IP/`requestId`;
  alcance `own` sobre archivo ajeno ⇒ 403; propósito público ⇒ 409; si el insert de auditoría
  falla, no hay URL (500).
- Aislamiento por organización a nivel repositorio (sin crear otra organización en la BD
  compartida, como en 0.5).
- Purga: pendiente viejo borrado (objeto + fila + auditoría); pendiente reciente y `ready` intactos.
  Endpoint: sin/mal bearer ⇒ 401; con bearer ⇒ 200 `{ purged }`.
- Matriz de autorización (`test/support/authzMatrix.ts`): filas para las rutas nuevas.
- Unitarios: `detectContentType` (cada firma + HTML/SVG/ZIP ⇒ `null`), `sanitizeFileName`,
  `mediaKey`, `canDownload`, `createUploadBody` (tipo/tamaño fuera del propósito), CSP del CRM,
  `uploadMedia`.
- Fixtures binarios mínimos en `apps/api/test/fixtures/media/` (JPEG con EXIF, PNG, PDF, HTML).

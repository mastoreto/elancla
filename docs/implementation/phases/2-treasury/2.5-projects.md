# 2.5 — Proyectos

## Objetivo

Proyectos con fondo propio, ofrendas especiales, historial de versiones y reglas de cierre.

## Depende de

2.1.

## Alcance

- Proyecto: título, ministerios (o asamblea/directiva), descripción, documentos (archivo o enlace),
  fechas, presupuesto, moneda; fondo propio (D-49).
- Estados: planificación → en proceso → finalizado → cerrado; versión por cada edición (RF-20).
- Lo crea cualquier rol; lo editan tesorería, directiva y su creador (policy de propiedad).
- Se elimina solo sin movimientos y sin estar en curso; si no, se cierra. Al cerrar, devolución de
  sobrantes (2.4).
- **Ofrendas especiales**: ingresos identificados con el proyecto.
- **Seguimiento de aportantes** opcional por proyecto (D-50): familia o persona, cifrado, visible
  solo con permiso, cada lectura auditada.

## Fuera de alcance

—

## Requisitos ESRE / decisiones

RF-01, RF-20; D-49, D-50.

## Cambios de BD

`Project`, `ProjectRevision`, `ProjectMinistry`, `ProjectDocument`, `Donor` (cifrado), `DonorContribution`.

## Endpoints y permisos

`treasury/projects` con `projects:*` + policy de creador; `donors:view`, `donors:manage`.

## Tests obligatorios

- Creador edita; otro sin permiso no.
- Borrado con movimientos → se cierra.
- Aportantes: sin `donors:view` no aparecen ni en la API ni en informes; en BD el dato está cifrado.
- Proyecto sin seguimiento no permite registrar aportantes.

## Terminado cuando

- Tests obligatorios en verde en CI.
- `bun run check` y `bun run check-types` limpios.
- Docs de `architecture/` actualizados si algo cambió.
- La pantalla del CRM usa la API, sin seeds.

# 2.3 — Órdenes de compra y rendición

## Objetivo

Desde la solicitud aprobada hasta la rendición cerrada, con respaldo documental de cada salida (D-42).

## Depende de

2.1, 2.2.

## Alcance

- **Orden de compra** (`OC-…`; la "boleta" del ESRE): justificación para comprar algo; responsable,
  monto, moneda, fondo; se entrega
  con un movimiento de egreso.
- **Rendición** de la orden:
  - **Factura**: comprobante formal del comercio (impreso o electrónico): proveedor, número, fecha,
    monto, archivo.
  - **Comprobante de caja**: recibo interno cuando no hay factura o es irregular; descripción, monto,
    imagen del papel si existe.
  - **Devolución del sobrante**: movimiento de ingreso vinculado.
- Estados: emitida → entregada → rendida parcial → rendida → cerrada; alerta de órdenes sin rendir.
- Reglas del ESRE sobre los equivalentes: la orden no se edita si ya tiene justificativos; no se
  elimina si tiene movimiento; el comprobante de caja no se edita ni elimina si está ligado a una salida realizada.
- Confirmación previa a eliminar y auditoría.

## Requisitos ESRE / decisiones

RF-14 a RF-19, ESRE 2.2; D-42.

## Cambios de BD

`PurchaseOrder`, `Justification` (tipo factura / comprobante de caja, archivo), relación con `Movement`.

## Endpoints y permisos

`treasury/purchaseOrders`, `treasury/justifications` con `purchaseOrders:*`, `justifications:*`.

## Tests obligatorios

- Suma de justificativos + sobrante devuelto = monto entregado para cerrar.
- Cada regla de bloqueo tiene su test (unitario en `domain/` + integración).
- Factura sin archivo → rechazada; comprobante de caja con firma/datos mínimos obligatorios.

- `bun run check` y `bun run check-types` limpios.
- Docs de `architecture/` actualizados si algo cambió.
- La pantalla del CRM usa la API, sin seeds.

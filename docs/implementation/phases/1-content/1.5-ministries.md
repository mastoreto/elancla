# 1.5 — Ministerios (perfil público)

## Objetivo

Gestionar el ministerio completo (perfil público) sobre la tabla única de D-20, con estructura fija de página (D-29).

## Depende de

1.1, 1.2, 1.3 (perfiles públicos). Los horarios del ministerio se completan con 1.6.

## Alcance

Campos (T = traducible, D-26):

- **Identidad**: nombre T, slug T, frase corta T, categoría (lista editable, T), visible en la web.
- **Destino**: página propia, enlace externo (p. ej. Espacio Mujer) o sin página.
- **Apariencia**: ícono, color (token del diseño), portada, mosaico de la landing (mostrar, orden,
  foto o color; D-28).
- **Datos prácticos**: lugar T, edades/público T, cómo sumarse T. Los horarios **no** se cargan acá:
  salen de las actividades del calendario vinculadas al ministerio (1.6).
- **Responsables**: `PersonProfile` de 1.3 (D-40) en contexto "responsable de ministerio": rol T,
  mostrar en la web sí/no (por defecto no). En el CRM siempre visibles.
- **Página**: "sobre el ministerio" en texto enriquecido T y valores opcionales T. Estructura fija:
  hero, sobre, valores, datos prácticos (cuándo, dónde, con quién; derivados), próximo paso y CTA.
- **SEO**: título y descripción T (autogenerados si faltan), imagen social (por defecto la portada).

Además:

- Reemplaza las cuatro listas actuales (`ministriesData.json`, `ministries.json`, mosaico, calendario)
  y unifica slugs.
- Se elimina el texto de relleno del template actual.
- El layout del mosaico se calcula según la cantidad de ministerios visibles (hoy está puesto a mano):
  requiere trabajo de diseño.
- Edición con el rol custom que se defina (Editorial) y flujo de 1.2.

## Fuera de alcance

Lo que 1.0 marque como fijo.

## Requisitos ESRE / decisiones

D-20, D-26, D-28, D-29, D-30.

## Cambios de BD

`Ministry` (perfil + mosaico), `MinistryTranslation`, `MinistryCategory` (+ traducción), responsables vía `PersonRole`.

## Endpoints y permisos

`content/ministryProfile` con `ministries.profile:*`.

## Tests obligatorios

- `ministries.profile` no lee ni edita campos financieros.
- Ministerio oculto o no publicado no sale en la API pública.
- Responsable con "mostrar en la web" apagado no aparece en la API pública.
- Fallback de idioma: sin traducción al inglés, se devuelve el español.

## Terminado cuando

- Tests obligatorios en verde en CI.
- `bun run check` y `bun run check-types` limpios.
- Docs de `architecture/` actualizados si algo cambió.
- La sección de la web muestra datos de la API, sin seeds.

# 1.1 — API pública y SDK

> **Estado: Completado** (rama `feat/public-api`, plan: [`plans/1.1-public-api-sdk.md`](../../plans/1.1-public-api-sdk.md)). Hoy solo `SiteSettings` sale de la BD, así que la API pública expone `GET /api/public/v1/:churchSlug/settings` y `GET /api/public/v1/openapi.json`; posts, ministerios, eventos y sermones suman su endpoint al SDK en 1.4, 1.5 y 1.6. No hay rate limit propio hasta 1.10 (`rateLimit` se llavea por IP y aquí la IP es la del servidor web).

## Objetivo

Que la web consuma contenido solo por la API pública, preparada para otras iglesias.

## Depende de

Base técnica (0.x).

## Alcance

- Módulo `public`: `/api/public/v1/:churchSlug/...` (la API vive bajo `/api`), solo contenido publicado, DTOs públicos.
- `SiteApiKey`: alta, rotación (dos activas), revocación desde Configuración → pestaña "Sitio web"; formato `sk_<keyId>_<secreto>`, solo se guarda el hash SHA-256 y el secreto se muestra una vez. Rotar = crear la nueva y revocar la vieja.
- Idioma por `?locale=` con fallback al idioma por defecto de la iglesia; el idioma forma parte de la URL cacheada (D-26).
- La key debe coincidir con el `churchSlug`; caché `public, s-maxage=60, stale-while-revalidate=300`.
- OpenAPI público versionado.
- `packages/content` reescrito como SDK manteniendo las firmas actuales (`getAllPostCards`, `getPostBySlug`…).
- `apps/web`: fuera `@ancla/db` y `@prisma/client`; middleware lee settings vía SDK con caché en memoria; env `API_URL` + `SITE_API_KEY` (solo servidor).
- Si la API no responde, la web usa el fallback actual y no se cae.

## Fuera de alcance

Webhooks salientes. Alta de otras iglesias.

## Requisitos ESRE / decisiones

D-22, D-25, D-26; [`multi-site.md`](../../architecture/multi-site.md).

## Cambios de BD

`SiteApiKey`.

## Endpoints y permisos

Rutas públicas con site key; gestión de keys con `site.keys:view`, `site.keys:create` y `site.keys:delete` (`siteKeys` en el catálogo de permisos; `manage` no es una acción válida y rotar no necesita `edit`). `GET/POST /api/site-keys`, `DELETE /api/site-keys/:id`; la tercera key activa responde 409 `site_key_limit`.

## Tests obligatorios

- Sin key, key revocada o de otra iglesia → 401.
- Nunca devuelve borradores ni campos fuera del DTO público.
- La web compila y renderiza sin `DATABASE_URL`.

## Terminado cuando

- Tests obligatorios en verde en CI.
- `bun run check` y `bun run check-types` limpios.
- Docs de `architecture/` actualizados si algo cambió.

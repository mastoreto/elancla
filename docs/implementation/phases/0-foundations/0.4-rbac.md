# 0.4 — Roles y permisos (RBAC)

## Objetivo

Que nadie vea ni haga nada que sus roles no cubran, con control fino por recurso, acción y alcance.

## Depende de

0.3.

## Alcance

- Catálogo de permisos **en código** (`core/authz`): `recurso:acción` con alcance `own | ministry | all`. Recursos finos (p. ej. `ministries.profile` y `ministries.finance`).
- Roles **en BD**, editables desde Configuración (la grilla que ya existe en el CRM); varios roles por usuario.
- Asignación de ministerios al usuario para el alcance `ministry`.
- `requirePermission()` por ruta; `scopeWhere()` en consultas; policies por recurso.
- Política de sesión por rol: sesión persistente sí/no y duración máxima; gana la más restrictiva (D-16).
- `GET /me/permissions`: el CRM arma menú y vistas solo con lo permitido.
- Protecciones: no se puede quitar el último admin; nadie edita sus propios roles.
- Seed de roles del ESRE: Tesorero, Síndico, Directiva, Pastoral, Líder, Asamblea, Oficina, más Admin y Editor de contenido.

## Adelantado desde 1.5

Se crea ya una tabla `Ministry` **mínima** (`id`, `organizationId`, `name`, `slug`): el alcance
`ministry` necesita algo a lo que apuntar. `GET /ministries` es de solo lectura y el seed crea
algunos ministerios de prueba; la fase 1.5 la extiende y agrega el CRUD.

## Fuera de alcance

Permisos por proyecto individual (se resuelven con policies de propiedad en 2.5).

## Requisitos ESRE / decisiones

RF-01, RF-02 (panel por rol); D-09, D-16, D-20.

## Cambios de BD

`Role`, `RolePermission`, `UserRole`, `UserMinistry`; campos de política de sesión en `Role`.

## Endpoints y permisos

`identity/roles` con `roles:*`; `GET /me/permissions` (cualquier sesión).

## Tests obligatorios

- Toda ruta registrada declara permiso (introspección del router); si no, el test falla.
- Arnés de la matriz de autorización (rol × ruta × alcance) listo para que cada módulo agregue sus filas.
- Alcance `ministry` no ve datos de otro ministerio.
- Último admin no se puede quitar; auto-elevación rechazada.

## Terminado cuando

- Tests obligatorios en verde en CI.
- `bun run check` y `bun run check-types` limpios.
- Docs de `architecture/` actualizados si algo cambió.

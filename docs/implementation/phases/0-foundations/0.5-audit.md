# 0.5 — Auditoría

> **Estado:** implementada en la rama `feat/audit` (plan: [`plans/0.5-audit.md`](../../plans/0.5-audit.md)).

## Objetivo

Registro estricto e inalterable de todo lo que pasa en el sistema.

## Depende de

0.2. Se integra con 0.3 y 0.4 a medida que existen.

## Alcance

- `AuditLog` append-only: actor, organización, acción, entidad, antes/después, motivo, IP, user agent, request id, resultado.
- `writeAudit(tx, ctx, event)` dentro de la transacción de cada mutación.
- Catálogo de eventos tipado (`movement.created`, `report.exported`, `auth.login.denied`…).
- Eventos de auth (login, fallo, 2FA) vía hooks de Better Auth; denegaciones de permiso desde `requirePermission()`.
- Lecturas sensibles: documentos privados, informes, exportaciones.
- `app_runtime` sin `UPDATE`/`DELETE` sobre `AuditLog`.
- Módulo `audit` de solo lectura + pantalla en Configuración con filtros.

## Fuera de alcance

Encadenado de hashes (evaluar si los síndicos necesitan verificar integridad). Lecturas sensibles: el mecanismo está, pero se cablean cuando existan documentos privados e informes.

## Requisitos ESRE / decisiones

RF-05 (motivo de edición); D-10.

## Cambios de BD

`AuditLog` con índices por `(organizationId, createdAt)`, `(organizationId, entityType, entityId)` y `(organizationId, actorId)`.

## Endpoints y permisos

`GET /audit` con `audit:view`.

## Tests obligatorios

- `UPDATE`/`DELETE` sobre `AuditLog` con `app_runtime` falla.
- Si la mutación hace rollback, no queda registro de auditoría (y viceversa).
- Denegación de permiso queda registrada.

## Terminado cuando

- Tests obligatorios en verde en CI.
- `bun run check` y `bun run check-types` limpios.
- Docs de `architecture/` actualizados si algo cambió.

# 0.7 — Tests y CI

> **Estado:** hecha en la rama `chore/testing-ci` (plan: [`plans/0.7-testing-ci.md`](../../plans/0.7-testing-ci.md)). Desvíos respecto de esta ficha: la BD de test es un servicio efímero de compose (`db-test`, tmpfs) usado igual en local y en CI; aislamiento por datos únicos + limpieza, sin rollback por test (ver D-12); el CI corre **solo en el PR `develop → main`** y Husky es la primera barrera en local; versionado SemVer (D-55) y hooks de Git incluidos en esta fase.

## Objetivo

Que nada crítico se pueda romper sin que CI lo frene.

## Depende de

Arranca junto con 0.2 y crece con cada subfase.

## Alcance

- Tarea `test` en `turbo.json` y scripts por workspace (`bun test`).
- Postgres de test (servicio `db-test` de `docker-compose`, el mismo en CI), `migrate deploy`, aislamiento por datos únicos.
- Factories de datos y cliente HTTP de test (`app.request`).
- Runner de la matriz de autorización.
- Playwright para el CRM con usuarios sembrados por rol.
- GitHub Actions en el PR `develop → main`: `quality` (Biome + tipos), `db` (migraciones desde cero + drift), `test` (unitarios e integración), `e2e` y `version`. Protección de rama en `main`: PR obligatorio con esos cinco checks.
- Husky en local: `pre-commit` (Biome + tipos), `commit-msg` (Conventional Commits, sin `Co-Authored-By`), `pre-push` (tests + build del CRM).
- Cobertura de la matriz: toda ruta registrada necesita una fila 401/403 o figurar en `PUBLIC_ROUTES`.

# 0.3 — Autenticación

## Objetivo

Login con Google y con email/contraseña, ambos solo por invitación, con 2FA opcional y sesiones seguras.

**Estado: implementada.**

## Depende de

0.2. La política de sesión por rol se completa con 0.4.

## Alcance

- Better Auth movido a `apps/api/src/core/auth`; se elimina `packages/auth`.
- Google y `emailAndPassword` (mínimo 12 caracteres, recuperación por email); `sign-up/email` público bloqueado (404): el alta con contraseña solo ocurre al aceptar una invitación.
- Alta solo con invitación pendiente: hook de creación de usuario que rechaza emails sin invitación (la auditoría llega en 0.5).
- Vínculo de cuentas solo explícito desde "Mi cuenta" (vincular Google, crear contraseña); la foto de Google se guarda.
- Módulo `identity/invitations`: crear, listar, reenviar (rota el token), revocar, vista previa y aceptar. Token de 32 bytes, solo su SHA-256 en BD, 7 días, uso único.
- Puerto `Mailer` (`core/mail`) con SMTP y Mailpit en desarrollo; plantillas en `packages/emails`.
- **Spike (resuelto)**: el plugin `twoFactor` no cubre el login social; `socialTwoFactorGuard` replica su hook sobre `/callback/:id` y `/sign-in/social`.
- 2FA opcional por usuario: activar, desactivar, códigos de respaldo.
- `freshAge` para operaciones sensibles (re-autenticación).
- Rate limit de Better Auth con almacenamiento en BD.
- Primer admin: script que crea su invitación (reemplaza `seed-admin.ts`).
- CRM: login con ambos métodos, `/invitation/[token]`, `/two-factor`, `/reset-password`, "Mi cuenta" e invitaciones en Configuración.

## Fuera de alcance

Roles y permisos (0.4). Passkeys.

## Requisitos ESRE / decisiones

RF-01; D-08, D-16.

## Cambios de BD

`TwoFactor`, `RateLimit`, `Invitation`, `User.twoFactorEnabled`.

## Endpoints y permisos

Rutas de Better Auth; `identity/invitations` con `users:invite`.

## Tests obligatorios

- E2E: usuario invitado entra con Google; no invitado es rechazado y queda auditado.
- E2E: activar 2FA, cerrar sesión, volver a entrar exige el código.
- Invitación revocada o vencida no permite el alta.
- Operación sensible con sesión vieja → exige re-autenticación.

## Terminado cuando

- Tests obligatorios en verde en CI.
- `bun run check` y `bun run check-types` limpios.
- Docs de `architecture/` actualizados si algo cambió.

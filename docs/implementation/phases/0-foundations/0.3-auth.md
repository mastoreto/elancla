# 0.3 — Autenticación

## Objetivo

Login solo con Google, solo por invitación, con 2FA opcional y sesiones seguras.

## Depende de

0.2. La política de sesión por rol se completa con 0.4.

## Alcance

- Better Auth movido a `apps/api/src/core/auth`; se elimina `packages/auth`.
- Google como único proveedor; `emailAndPassword` deshabilitado; `signUp` fuera del cliente.
- Alta solo con invitación pendiente: hook de creación de usuario que rechaza (y audita) emails sin invitación.
- Módulo `identity/invitations`: crear, reenviar, revocar, aceptar (plantilla `invitation-email` ya existe).
- **Spike primero**: comprobar cómo aplica el plugin `twoFactor` con login social. Si no lo cubre, sesión en estado "pendiente de 2FA" hasta verificar el TOTP.
- 2FA opcional por usuario: activar, desactivar, códigos de respaldo.
- `freshAge` para operaciones sensibles (re-autenticación).
- Rate limit de Better Auth con almacenamiento en BD.
- Primer admin: script que crea su invitación (reemplaza `seed-admin.ts`).
- CRM: pantalla de login con Google; cierre de sesión limpia el caché de queries.

## Fuera de alcance

Roles y permisos (0.4). Passkeys.

## Requisitos ESRE / decisiones

RF-01; D-08, D-16.

## Cambios de BD

Tablas de Better Auth (`twoFactor`), `Invitation`.

## Endpoints y permisos

Rutas de Better Auth; `identity/invitations` con `users:invite`.

## Tests obligatorios

- E2E: usuario invitado entra con Google; no invitado es rechazado y queda auditado.
- E2E: activar 2FA, cerrar sesión, volver a entrar exige el código.
- Invitación revocada o vencida no permite el alta.
- Operación sensible con sesión vieja → exige re-autenticación.

## Terminado cuando

- Tests obligatorios en verde en CI.
- `bun run check` y `bun run check-types` limpios.
- Docs de `architecture/` actualizados si algo cambió.

# 0.1 — Rework de la base de datos

## Objetivo

Dejar el schema base listo para que todas las features se construyan encima sin migraciones dolorosas.

## Depende de

Nada. Es la primera subfase.

## Alcance

- Modelo `Organization` (slug único, país, zona horaria, monedas habilitadas, `defaultLocale`, `locales` habilitados; D-18, D-51) y `organizationId` en todos los modelos de dominio (D-02).
- PKs `uuid(7)` con `@db.Uuid`; Better Auth configurado con `generateId` UUID (D-03).
- `Decimal(14,2)` para todo monto; se eliminan los `Float` (D-04).
- `DocumentSequence` para correlativos (D-03).
- `SiteSettings` pasa a 1:1 con `Organization` (deja de ser singleton) (D-25).
- Se elimina `User.role` (lo reemplaza RBAC en 0.4).
- Migración inicial con `prisma migrate`; `db push` fuera de los scripts y de `docker-compose` (D-05).
- Evaluar Prisma 7 y adoptarlo si no bloquea nada.
- Roles de Postgres `app_runtime` y `app_migrator`; RLS activado en todas las tablas (D-21).
- Patrón de traducciones (D-26) documentado y aplicado a `SiteSettings`; helper de resolución con fallback al idioma por defecto.
- Seed: organización El Ancla (`es` por defecto; `en`, `pt`) + su `SiteSettings`.

## Fuera de alcance

Modelos de cada feature (se agregan en su subfase con su propia migración). `AuditLog` (0.5).

## Requisitos ESRE / decisiones

D-02, D-03, D-04, D-05, D-18, D-21, D-25, D-26, D-51.

## Cambios de BD

Migración baseline. Los datos actuales de desarrollo se descartan (no hay datos reales).

## Tests obligatorios

- La migración aplica desde cero en una BD vacía.
- Toda tabla tiene `rowsecurity = true` (consulta a `pg_tables`).
- Ningún modelo de dominio sin `organizationId` (test sobre el DMMF de Prisma).
- Ningún campo de dinero con tipo `Float`.

## Terminado cuando

- Tests obligatorios en verde en CI.
- `bun run check` y `bun run check-types` limpios.
- Docs de `architecture/` actualizados si algo cambió.

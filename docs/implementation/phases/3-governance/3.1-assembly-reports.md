# 3.1 — Informes para presentar en asamblea

## Objetivo

Mostrar informes de tesorería generados "para presentar" solo a los presentes de la asamblea (presencial o virtual), minimizando filtraciones (D-11).

## Depende de

2.7, 1.3 (coordenadas de la iglesia).

## Alcance

- Propósito del informe al generarlo: uso interno o para presentar.
- Publicación desde el CRM: snapshot del informe, código de ≥ 128 bits, ventana de vigencia, habilitación manual, baja automática, modalidad.
- **Presencial**: radio de geocerca. **Virtual**: acceso con credencial de asistente (D-53).
- Modo proyección.
- `/informe/[code]` sin datos en la página; `POST /public/v1/assembly-reports/:code/open` con coordenadas; validación en servidor; respuesta `no-store`.
- Rate limit por IP y por código; 403 genérico sin explicar el motivo.
- Ocultar el contenido al perder foco o visibilidad.
- Marca de agua (código, hora, identificador del dispositivo); sin impresión, selección ni descarga.
- **Investigación** (D-19): detección de intentos de captura y viabilidad de un enfoque tipo DRM.
- Auditoría de cada apertura y de cada rechazo.

## Fuera de alcance

Bloqueo real de capturas (requiere app nativa).

## Requisitos ESRE / decisiones

D-11, D-17, D-19, D-53; [`security.md`](../../architecture/security.md) §3.

## Cambios de BD

`AssemblyReport`, `AssemblyReportOpen`.

## Endpoints y permisos

Publicación con `assembly:publish`; apertura pública con código + geocerca.

## Tests obligatorios

- El HTML de `/informe/[code]` no contiene datos del informe.
- Fuera de radio, sin coordenadas o fuera de vigencia → 403 y ningún dato.
- Código inválido repetido → rate limit.
- E2E: dentro del radio se ve; al perder foco se oculta.

## Terminado cuando

- Tests obligatorios en verde en CI.
- `bun run check` y `bun run check-types` limpios.
- Docs de `architecture/` actualizados si algo cambió.
